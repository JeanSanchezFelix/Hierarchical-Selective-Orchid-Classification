# Orchid Edge-Ready HSC Paper Protocol

## Status

Phase 1 protocol freeze. This document is the source of truth for the paper
scope until a later approved phase changes it.

## Research Question

Under a fixed MobileNetV2 backbone and training budget, can a shared,
taxonomy-consistent dual-head classifier with calibrated hierarchical selective
prediction provide safer long-tailed orchid identification while reducing the
model count, package footprint, and neural inference calls required by hard
genus-to-expert cascades?

## Paper Framing

Working title:

> Edge-Ready Taxonomy-Consistent Hierarchical Selective Classification for
> Long-Tailed Orchid Recognition

The contribution is an edge-oriented systems and evaluation study. It does not
claim a new HSC algorithm, universal open-set recognition, phylogenetic
learning, real-time Android performance, or physical-device benchmarking.

"Edge-ready" means that every method uses an edge-compatible MobileNetV2
configuration, can be exported to LiteRT, and is compared using artifact size,
model count, inference-call count, host CPU measurements, and conversion
parity. Host CPU measurements are not mobile-device measurements.

## Public Dataset

The study uses a public iNaturalist-derived Orchidaceae dataset generated by
`scripts/prepare_public_orchid_dataset.py` in Phase 2. It is not based on the
private dataset currently present under `data/`.

Target benchmark:

- approximately 50,000 JPEG images;
- approximately 200 species across multiple orchid genera;
- one selected photo per observation;
- a naturally imbalanced distribution, bounded by documented inclusion caps;
- folder layout `<root>/<Genus>/<Species>/<image-file>`;
- immutable versioned manifests with observation, license, taxonomy, split, and
  checksum metadata.

The exact class and image counts are outputs of the frozen source snapshot and
selection policy. They must not be written as final paper facts until the
dataset manifest is generated and validated.

## Data Split Policy

All comparisons use the same immutable split manifest:

| Split | Proportion | Purpose |
| --- | ---: | --- |
| Train | 70% | Parameter fitting |
| Validation | 10% | Model selection and early stopping |
| Calibration | 10% | Temperatures and HSC thresholds only |
| Test | 10% | One final evaluation after all decisions are frozen |

Rows are grouped by `observation_id`; photos from the same observation never
cross splits. The manifest records observer identity as a hashed audit field
when the source allows it, but observer-disjoint splitting is not assumed.

## Compared Methods

All conditions use the same input size, augmentation family, pretrained
MobileNetV2 variant, optimizer family, epoch budget, split manifest, and seed
set unless an ablation explicitly changes one of them.

| ID | Method | Role |
| --- | --- | --- |
| C1 | Hard top-1 genus cascade | Existing cascade control |
| C2 | Fixed top-2 genus cascade | Existing cascade control |
| B0 | Flat species MobileNetV2 with cross-entropy | Forced-label baseline |
| B1 | Flat species MobileNetV2 with Balanced Softmax | Long-tail control |
| B2 | B1 plus post-hoc HSC | HSC without taxonomic multitask training |
| B3 | Shared species/genus heads without consistency loss | Taxonomic supervision ablation |
| Ours | Shared species/genus heads, consistency loss, and calibrated HSC | Proposed method |

The proposed training objective is:

```text
L = L_species(Balanced Softmax) + lambda_genus * L_genus(CE)
    + lambda_consistency * D(p_genus, aggregate(p_species))
```

`lambda_genus` and `lambda_consistency` are selected on validation data and
frozen before calibration and test evaluation. Logit adjustment and cRT are not
combined with Balanced Softmax; they are optional separately declared ablations.

## Hierarchical Decision Contract

The proposed model performs one neural forward pass and yields species and
genus logits. Temperatures and decision thresholds are fitted on calibration
data only. The final decision is exactly one of:

- a species, when the calibrated species decision passes;
- its genus, when the species decision abstains but the calibrated genus
  decision passes;
- `Unknown`, otherwise.

`Unknown` is uncertainty abstention. It is not a non-orchid prediction unless
an independently collected non-orchid evaluation corpus is added and evaluated
in a later approved phase.

## Metrics

Primary endpoint:

- hierarchical area under the risk-coverage curve (hAURC) for `Ours` versus
  `B2`, reported across seeds with paired bootstrap confidence intervals.

Required predictive metrics:

- species top-1 and top-5 accuracy;
- species macro-F1 and balanced recall;
- many, medium, and few-shot strata;
- genus top-1 and top-2 accuracy;
- taxonomy-consistency violation rate;
- ECE and NLL before and after calibration;
- hierarchical risk-coverage curves and species/genus/Unknown coverage.

Required edge-oriented metrics:

- parameter count and MACs/FLOPs;
- FP32 and INT8 LiteRT file size;
- number of packaged model files and total package footprint;
- neural inference calls per input;
- fixed-protocol host CPU latency and peak host memory;
- PyTorch-to-LiteRT prediction parity and INT8 metric delta.

Phylogenetic distance remains an optional error-severity analysis with reviewed
name mapping and declared coverage. It is not a training loss or inference
weight in the core method.

## Reproducibility Contract

Every run records:

- method ID, complete configuration, seed, code revision, and environment;
- dataset snapshot ID, manifest hash, taxonomy hash, and preprocessing hash;
- checkpoint hash and export hash;
- validation and calibration decisions;
- image-level predictions for every evaluation split;
- generated metrics, figures, and tables.

The standard seed set is `17`, `42`, and `123`. A single-run command may
override only the seed. Full paper results require all three seeds.

Use `scripts/run_orchid_experiment.py all` for each single-model condition and
`scripts/run_orchid_cascade.py --seed <seed>` for the router-plus-expert
controls. After all seven conditions finish, run
`scripts/summarize_orchid_paper_results.py`; it refuses missing or unpaired
held-out prediction files rather than producing a misleading aggregate.

## Edge-Ready Audit

For every frozen condition, run `scripts/audit_orchid_edge.py` with one
`--checkpoint` per packaged neural model. The JSON reports model count,
inference calls per input, parameter count, checkpoint footprint, and a fixed
CPU-only latency protocol. These are host measurements, not Android results.
LiteRT conversion and INT8 results may be reported only after a separately
recorded parity comparison using identical preprocessing.

`scripts/export_orchid_paper_litert.py` exports flat and dual-head checkpoints;
`scripts/compare_orchid_litert_logits.py` writes the parity report from
identically ordered PyTorch and LiteRT logits. Do not combine an INT8 result
with an FP32 parity report.

## Claim Boundaries

Allowed claims:

- the proposed method's measured accuracy, selective-risk, and edge-artifact
  trade-offs on the frozen public benchmark;
- conversion compatibility and host-measured resource characteristics;
- the effect of named ablations under the declared protocol.

Disallowed claims:

- physical-device latency, Android memory use, or real-time mobile behavior;
- superiority beyond the measured Orchidaceae benchmark;
- non-orchid detection without a negative dataset;
- a new HSC, Balanced Softmax, logit-adjustment, or phylogenetic algorithm.
